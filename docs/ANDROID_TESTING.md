# Android device and accessibility testing

The APK is generated by GitHub Actions. A successful build is only a compile/package check; the flashlight must still be tested on a physical Android handset.

## Hardware and permission checks

- [ ] Install the debug APK on a phone with a rear LED.
- [ ] Open the app and confirm the LED is off by default.
- [ ] Tap the main power button and grant camera permission when Android asks.
- [ ] Confirm the first permission grant does not silently switch on the LED; the user must deliberately tap again.
- [ ] Confirm the power button switches the LED on and off.
- [ ] Deny permission and verify the app stays usable and does not enter an endless permission-request loop.
- [ ] Grant permission later in Android Settings, return to the app, and try again.
- [ ] Test with another camera app holding the camera; the app should show a useful failure message rather than crash.
- [ ] Test a handset without a flash LED.
- [ ] Background the app and lock the screen; confirm behavior is understood and the light can be turned off when returning.
- [ ] Confirm leaving/destroying the app releases the torch.

## TalkBack and small-screen checks

- [ ] Main power button announces “Turn flashlight on” and “Turn flashlight off”, not only a decorative power glyph.
- [ ] Status changes are announced politely and do not flood TalkBack during SOS/strobe.
- [ ] SOS and STROBE buttons announce their names.
- [ ] Strobe displays a clear photosensitivity warning and requires an explicit confirmation.
- [ ] All controls can be reached with TalkBack and Android keyboard navigation.
- [ ] Test at 320–360 dp widths and with large font/display scaling.
- [ ] Confirm the content can scroll on short screens and system bars do not cover controls.
- [ ] Focus and pressed states remain visible with high-contrast settings.

## Safety and release checks

- [ ] Do not test strobe around anyone who may be photosensitive.
- [ ] Confirm the warning appears before any strobe flashing begins.
- [ ] Verify SOS and strobe stop when the user returns to steady/off mode.
- [ ] Check battery impact during extended torch use.
- [ ] Verify app label, icon, package ID and version before distributing.
- [ ] Before Play Store release, configure signing, privacy disclosures and target API compliance; the workflow currently produces a debug APK, not a signed production release.

## Known limits

- Flash hardware availability and camera permission behavior vary by handset and Android build.
- The app requests CAMERA permission because Android's CameraManager torch API is permission-gated; the app does not capture or upload photos/video.
- The GitHub Actions workflow generates the Gradle project during CI. Generated Android source files are not currently checked into the repository.
